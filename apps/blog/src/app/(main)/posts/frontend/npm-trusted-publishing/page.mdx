NPM이 보안 강화를 위해 기존 **Classic Token**의 사용을 제한했습니다. **2025년 12월 9일**을 기점으로, 기존 Classic Token은 더 이상 사용할 수 없게 되었습니다.

Classic Token은 권한 범위가 포괄적이고, 유효기간 설정이 강제되지 않아, 토큰 유출 시 계정 전체가 탈취될 위험이 컸습니다. 따라서 NPM은 Classic Token을 더 이상 지원하지 않고, **Granular Token**이나 **Trusted Publishing** 방식 중 하나를 사용할 것을 권장하고 있습니다.

## Granular Token과 Trusted Publishing

Classic Token이 사라진 지금, 두 방법 중 하나를 사용해야 npm에 패키지를 배포할 수 있습니다.

- Granular Token  
  기존 토큰 방식의 개량형입니다. 패키지별 권한 제어가 가능하고, 유효기간 설정이 강제됩니다.
- Trusted Publishing  
  OpenID Connect를 기반으로, CI/CD 환경(ex: GitHub Actions)에서 토큰 없이 패키지를 publish할 수 있게 해주는 방법입니다.

## Trusted Publishing을 추천하는 이유

Granular 토큰을 사용하면, 여전히 토큰을 발급받아 GitHub Secrets에 넣어줘야 합니다. 따라서 토큰을 주기적으로 갱신해줘야 하는 관리 부담이 발생합니다. 반면, **Trusted Publishing은 GitHub Repository와 NPM을 한 번 연결해두면 별도의 토큰 관리가 필요하지 않습니다.**

또한 Trusted Publishing은 배포가 일어나는 그 짧은 순간에만 유효한 임시 토큰을 발행하고, 배포가 끝나면 즉시 만료시키는 구조입니다. 따라서 토큰이 유출될 가능성을 최소화합니다.

## Trusted Publishing 설정 방법

### 1. NPM 설정

![NPM 패키지 Settings 페이지의 Trusted Publisher 영역에서 GitHub Actions 버튼을 선택하는 화면](/npm-trusted-publisher-select.webp)

NPM 패키지 Settings 페이지의 **Select your publisher** 항목에서, GitHub Actions 버튼을 클릭합니다.

![GitHub Actions용 Trusted Publisher 연결 정보를 입력하는 화면](/npm-trusted-publisher-form.webp)

- **Organization or user**: 패키지가 속해있는 유저 또는 조직의 이름을 적어줍니다.
- **Repository**: 패키지의 Repository 이름을 적어줍니다.
- **Workflow filename**: 배포 스크립트의 이름을 적어줍니다.
  - 만약 배포 스크립트가 `.github/workflows/publish.yml`이라면, 해당 항목에 `publish.yml`만 적어주시면 됩니다.
- **Environment name**: 공란으로 놔두시면 됩니다.
- **Allowed actions**: `npm publish`로 직접 배포하는 것도 허용하도록 선택해줍니다.

위 캡처는 2025년 12월에 찍은 화면이라 Allowed actions 항목이 보이지 않습니다. 이 항목은 이후에 추가되었고, 2026년 9월 3일 이후에 만든 설정은 기본적으로 `npm stage publish`만 허용합니다.

`npm stage publish`는 패키지를 바로 공개하지 않고 스테이징 영역에 올리는 명령어입니다. 스테이징된 패키지는 메인테이너가 2FA 인증을 거쳐 승인해야 공개됩니다. 이 글처럼 워크플로우에서 `npm publish`로 바로 배포하려면, Allowed actions에서 `npm publish`도 허용해줘야 합니다.

### 2. GitHub Actions 설정 1: permission

배포 스크립트 수정이 필요합니다. 먼저, `permissions`를 추가해줍니다. 해당 스크립트를 `on` 절 다음에 작성해줍니다.

```yaml
name: release publish

on:
  workflow_dispatch:
  release:
    types: [published]

permissions:
  contents: write
  id-token: write
```

Trusted Publishing을 위해, 액션 스크립트에서 `contents: write`와 `id-token: write` 권한이 필요합니다.

- 각각 git 작업, OIDC 토큰 생성을 위해 필요한 권한입니다.
- 만약 git push와 같은 작업이 필요하지 않다면, contents 권한을 `read`로 하셔도 됩니다.

### 3. GitHub Actions 설정 2: npm update & publish

```yaml
- name: Update npm for Trusted Publishing
  run: npm install -g npm@latest

- name: Deploy NPM (Trusted Publishing)
  run: npm publish
```

`npm publish`에 앞서 npm을 최신 버전으로 업데이트해줘야 합니다.

> Note: Trusted publishing requires npm CLI version 11.5.1 or later and Node version 22.14.0 or higher. ([출처](https://docs.npmjs.com/trusted-publishers))

Trusted Publishing이 NPM CLI 11.5.1 버전 이상을 요구하기 때문입니다. Node도 22.14.0 버전 이상이어야 하니, 워크플로우에서 사용하는 Node 버전도 함께 확인해주세요. 그다음은 간단하게 `npm publish`만 해주면 됩니다.

## 마치며

NPM Classic Token이 왜 지원 중단되었는지, 그리고 가장 확실한 대안인 **Trusted Publishing**에 대해 알아보았습니다.

간단한 설정만으로 보안을 강화하고, 토큰 갱신 부담을 줄일 수 있으니, 작업 중인 프로젝트에 적용해 보시기를 권장드립니다.
